# User Provisioning Design

## Overview

When an admin adds a new user, the system creates both the Firebase Auth account and the app database record in a single operation. The admin sets an initial password; the new user logs in with it and can change it at any time. If the email already exists in Firebase, creation is denied with a clear error message.

## Permission Matrix Impact

No changes to RBAC. Only admins can reach the Users page (route-guarded). This feature replaces the manual two-step process (Firebase console → app DB) with a single in-app form.

## Section 1 — Backend

**File:** `backend/app/routers/users.py`  
**File:** `backend/app/schemas/user.py`

### Schema changes

Remove `firebase_uid` from `UserCreate` (it is now generated by Firebase, not supplied by the client). Add `password: str` to `UserCreate`.

```python
class UserCreate(BaseModel):
    email: str
    name: str = ""
    role_id: int
    is_active: bool = True
    password: str  # initial password set by admin
```

`UserUpdate` keeps `firebase_uid` since it may be needed for existing record updates, and does not include `password` (password changes go through Firebase directly).

### Endpoint changes

`POST /api/v1/users/` flow:

1. Call `firebase_auth.create_user(email=body.email, password=body.password)`
   - On `firebase_admin.auth.EmailAlreadyExistsError` → raise `HTTPException(409, "A Firebase account with this email already exists")`
   - On any other Firebase error → raise `HTTPException(500, "Failed to create Firebase account")`
2. Store the returned `uid` from Firebase
3. Insert `User` DB record with `firebase_uid=uid` and the rest of the body fields
4. If DB insert raises → call `firebase_auth.delete_user(uid)` to clean up the Firebase account, then re-raise as `HTTPException(500, "User created in Firebase but database insert failed")`
5. Return the created `UserRead` object

The `firebase_uid` field is removed from the client-facing `UserCreate` schema. It is populated internally from Firebase's response.

## Section 2 — Frontend

**File:** `frontend/src/pages/Users.tsx`

### Form changes

Remove the "Firebase UID" field — it is no longer needed from the client.

Add "Initial Password" field:
- `type="password"` input with a show/hide toggle button (eye icon)
- Required field
- Labeled "Initial Password *"

Role dropdown remains with "Select role..." placeholder — admin must pick explicitly, no default.

### Success state

On successful creation, show a dismissible success banner **above the user table** (not inside the form) displaying:

```
User created successfully.
Email: user@example.com  |  Initial password: ••••••••  [Show]
Share these credentials with the new user.
```

The password is masked by default with a Show/Copy button. Banner stays until dismissed (✕ button) or until the admin navigates away.

### Error state

On 409 from backend: show inline form error:
`"This email already has a Firebase account. Choose a different email."`

On other errors: existing generic error display (`formError` state).

## Non-Goals

- No password complexity enforcement (Firebase enforces minimum 6 characters)
- No automatic email delivery (admin shares credentials manually)
- No password change flow for users (Firebase handles this natively)
- No edit of existing users' passwords via this UI
